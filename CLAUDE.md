# Butters

Tauri v2 tray/menu-bar app (macOS + Windows beta) that scores machine smoothness, finds idle heavy dev clutter (dev servers, MCP servers, agent sessions, Docker containers, Ollama models) and closes it only on user confirmation.

## Shape
- `src-tauri/src/engine/` — pure logic, no OS calls: `classify` (what a process is), `assess` (grouping, protection, suggestions). Keep OS access out of it.
- `app.rs` — shared state, nearly all commands, background loop. `actions.rs` — closing (graceful first; force is a separate request). `panel.rs` — tray + panel window lifecycle. `platform/{macos,win,other}` — OS-specific bits (objc2 on macOS, `windows` crate on Windows).
- `src/App.svelte` is the whole panel UI; `src/lib/api.ts` wraps `invoke`. Frontend↔Rust is commands only (polling, no events); background work runs in Rust threads.
- `playground.rs` + `--features playground` — separate "Butters Playground" test app (own identifier via `tauri.playground.conf.json`, no updater/shortcut) that only sees node processes it spawns itself.

## Gotchas / invariants
- **Adding/removing a Tauri command touches four places**: `COMMANDS` in `src-tauri/build.rs` (generates `src-tauri/permissions/autogenerated/<cmd>.toml`, which is committed), `src-tauri/capabilities/panel.json`, and the mock in `e2e/backend.ts`. Missing any one silently denies the call or breaks Playwright specs (they run against Vite preview with a fake `__TAURI_INTERNALS__`, not real Tauri).
- **Safety re-check at close time**: the frontend only holds opaque ids from the last scan; `actions.rs` re-verifies same pid + start time, current user, and refuses pid 0/1, Butters, its launcher and the frontmost app. Never let the frontend pass raw pids. Only argv[0] drives classification; later args are data.
- **WebKit magenta-line bug**: no CSS `filter`/blur on list rows; transitions inside the list use `blur: 0` (`src/lib/Row.svelte`). `e2e/zz-line.spec.ts` guards it.
- **WebKit click hit-testing**: switches/checkboxes must be wrapped in `<label>` with `pointer-events: none` on knob/box/track (`src/lib/Check.svelte`).
- **Panel timing (`panel.rs`)**: `LEAVE` (270 ms) must exceed the CSS `panel-melt` animation (260 ms in `App.svelte`) or the window is destroyed mid-melt. Frontend must call `hold_panel(true/false)` around closes — quitting an app steals focus, and blur would close the panel (600 ms grace after release). Blur is ignored for 300 ms after open. Panel window is destroyed on close, not hidden.
- macOS window margins in `panel.rs` must match CSS margins of `html.floating .panel`.
- `NSSound` must only be touched on the main thread (`run_on_main_thread`); `unsafe impl Send` in `sound.rs` depends on it.
- Updater uses `default-features = false` (no `zip`) to drop a vulnerable crate; Windows updates use the plain NSIS setup.exe. Don't re-enable defaults.
- `macOSPrivateApi: true` + `macos-private-api` feature are both needed for the transparent shadowed window.
- DMG icon positions in `tauri.conf.json` must match `scripts/make_dmg_background.py`. Tray icons are intentionally non-template (coloured), generated by `scripts/make_icons.py`.
- Code under `cfg(feature = "playground")` must be clippy-clean: CI runs clippy `-D warnings` with and without the feature.
- e2e timing checks must pin animations (pause, set `currentTime`, sample), never sleep — sleep-based checks flaked on CI. Alignment checks compare against text edge (box left + padding-left).

## Workflows
- Release: `scripts/release.sh X.Y.Z` from a clean tree — bumps `package.json`, `tauri.conf.json`, `Cargo.toml`, `Cargo.lock` together, commits, tags `vX.Y.Z` and **pushes immediately**. `release.yml` builds targets serially (`max-parallel: 1`, needed for `latest.json` merging), notarizes+staples the DMG separately, then un-drafts. Never bump versions by hand.
- Local `pnpm tauri build` needs `TAURI_SIGNING_PRIVATE_KEY` (updater artifacts are on); macOS signing is ad-hoc (`-`) locally.
- Playwright (`pnpm test:e2e`) needs `playwright install webkit chromium`; serves on 127.0.0.1:4173 (strict port, always rebuilds), viewport 380×580. WebKit stands in for macOS, Chromium for WebView2.
- Real-app test (macOS only): `pnpm tauri build --debug --bundles app --no-sign` then `python3 e2e/macos_app.py`. Needs pyobjc, Accessibility permission, `node`. It quits running Butters, uses a throwaway HOME, and clicks at fixed offsets from the panel's top-left — layout changes break it. Debug-only env: `BUTTERS_E2E_ONLY_PID` (only suggest that pid), `BUTTERS_E2E_ALERT`, `E2E_SHOT=1`.
- `pnpm playground` is effectively macOS-only (`--bundles app`).
