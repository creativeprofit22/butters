---
name: commit
description: Review all uncommitted work, run Butters' checks (mirroring CI), commit in order by intent, and push once
---

Clicking `/commit` authorizes this entire workflow. Execute directly: never enter plan mode, create a plan, pause for confirmation, or ask how to group changes.

Scope comes from git, not this conversation: handle every uncommitted change in the repository (staged, unstaged, and untracked), whether it came from this session, an earlier session, or a manual edit. Use conversation context only as a hint for grouping and messages.

1. Inspect `git status`, staged/unstaged diffs, untracked files, and recent commit subjects. If nothing is uncommitted, say so and stop.
2. Leave out and report anything that must not be committed: secrets or credentials (e.g. `TAURI_SIGNING_PRIVATE_KEY`), `dist/`, `src-tauri/target/`, `test-results/`, logs, scratch files, or clearly unfinished edits. Never delete, revert, or discard them.
3. Group changes by purpose, splitting exact hunks only when a file spans independent purposes. Keep uncertain or coupled changes together and order foundations before dependents. Never bump versions by hand; that is `scripts/release.sh`'s job.
4. Run the project checks once each (same as `.github/workflows/ci.yml`). Always:
   - `pnpm check`
   - `pnpm lint`
   - in `src-tauri/`: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo clippy --all-targets --features playground -- -D warnings`, `cargo test`
   Only when matching files changed:
   - `*.py`: `ruff check --no-fix .` and `ruff format --check .`
   - `scripts/*.sh`: `shellcheck scripts/*.sh`
   - `src/`, `e2e/`, `index.html`, `vite.config.ts` or `playwright.config.ts`: `pnpm test:e2e` (needs Playwright webkit + chromium installed; if missing, say so and continue)
   If formatting or lint fails, run `pnpm format` (frontend) or `cargo fmt` (Rust) on the changed files, include those fixes in the matching group, and rerun only that check. If any check still fails, stop and report it; do not clean up unrelated failures.
5. Spawn ONE subagent with the full diff for a fast review of real bugs, regressions, debug leftovers, and unintended changes. Brief it on this project's invariants from `CLAUDE.md`: a Tauri command added/removed must touch `src-tauri/build.rs` `COMMANDS`, `src-tauri/permissions/autogenerated/`, `src-tauri/capabilities/panel.json` and `e2e/backend.ts`; the frontend must never pass raw pids; `actions.rs` safety re-checks stay intact; `engine/` stays free of OS calls; no CSS `filter`/blur on list rows; `panel.rs` `LEAVE` stays above the CSS `panel-melt` duration. Require confidence scores and report only findings at least 80; pre-existing issues and style nitpicks score low.
6. If review is CLEAR, continue. Otherwise show the findings and use one `ask_user` choice with a `detail` of one plain sentence naming which findings are blocking: fix first (recommended) or commit anyway. On fix-first, fix and rerun affected checks without another review.
7. For each group, stage exact paths or hunks, never `git add -A` or interactive `git add -p` (stage a hunk with `git apply --cached`). The index must hold only that group, including anything staged before the run; inspect its staged diff before committing.
8. Create ordered commits with concise Add/Update/Fix/Remove/Refactor messages. Never use `--no-verify`. Then push the current branch exactly once after all commits if it tracks a remote; if it has none, say so instead of pushing. Never force-push and never push tags.

Finish with the created commits, anything left uncommitted and why, passed checks, review result, and push result.
